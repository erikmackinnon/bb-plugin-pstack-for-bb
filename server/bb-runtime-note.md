# pstack on bb

pstack was written for Cursor. Keep its workflow and evidence requirements. Follow user instructions and provider permissions. Resolve files relative to the active SKILL.md; never guess cache paths.

- AskQuestion → your structured question tool; adapt options to its schema, or ask in chat. Read/Write/Shell/todos → native file, shell, and task tools.
- Task/generalPurpose/subagent → your native subagent tool when available. Otherwise, with delegation authorized, use `bb thread spawn --project <id> --parent-self --prompt-file <brief>`; select `--environment <id-or-path>` or `--new-environment worktree` for isolation. Inspect with `bb thread show <id> --json`, `bb thread output <id>`, and `bb thread wait <id> --timeout 30s`. Background/readonly/cloud are intentions, not portable tool arguments. Give read-only workers explicit no-write briefs; MCP access depends on the provider. Discover remote environments with `bb environment providers`; never assume a cloud VM exists.
- poteto-agent/comment-sicko are bundled prompt files, not registered bb agent types. Give a fresh worker the actual path to `agents/poteto-agent.md` or `agents/comment-sicko.md` and require it to read it. A poteto-agent brief also gives the absolute path of `skills/poteto-mode/SKILL.md`, which it reads in full.
- Cursor model slugs (sol/grok/opus) are role defaults. Check `bb provider list --json` and `bb provider models <providerId> --json`; choose an available provider/model and supported `--reasoning-level` separately. Use the parent model for auto/inherit-parent. When a skill adjusts reasoning level or fast/standard speed, keep the role's model and set `--reasoning-level`, plus `--service-tier` only if the provider lists that tier. Never submit an unverified slug or invent effort or `-fast` suffixes.
- Keep confirmed model, provider, and reasoning separate when recording role choices. Do not edit the redistributed pstack bundle.
- Scope history to the current project/environment. Use `bb thread list --project <id> --include-hidden --json` and `--environment <id>` to narrow, then `bb thread log <id> --all --format json`. Check identity before reading; use a session digest if history is unavailable. Every hold-verify-bb-usage cleanup bucket requires checking bb's pinned/active threads and their environments before removal.
- Unknown icon/color frontmatter is Cursor UI metadata. bb does not implement Cursor custom modes or Option+Enter. Keep disable-model-invocation intent: flagged skills require user invocation or explicit routing from the invoked workflow; native enforcement varies by provider.
- Cursor /add-plugin, /loop, /automate, /visualize, create-skill, deslop, control-ui/control-cli, mcps/, and Routines/SendToUser/update_state are not bb built-ins. Use installed skills (for /visualize, a Mermaid diagram or an installed chart/visual skill), exposed MCP/tools, `bb guide threads`, and (if installed) `bb automation --help`. Do not invent webhook/routine/secret APIs; request secrets through the installed secrets skill. Benny is dormant reference material; enable nothing without its required integrations and user authorization.
- Bundled Bun helpers require Bun and their own lockfile, plus tools such as gh/gt where used. Check prerequisites first; Node alone cannot run Bun.spawnSync/bootstrap. Report a missing capability and stop that step without claiming success.
